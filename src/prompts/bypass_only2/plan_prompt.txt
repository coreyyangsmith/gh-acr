## Schema Specification

### Root
The root is a **JSON object** containing exactly these three keys:

1. **`strategy`** – **string** describing the high-level approach or methodology for resolving the change.
2. **`steps`** – **array** of ordered **string** items, each representing a sequential action to be taken.
3. **`resolution`** – **string** summarizing the final outcome after applying the steps.

---

### `strategy` String
- A concise yet clear description of the general plan for implementing the resolution.
- Should explain how to merge, add, remove, or modify elements, while addressing compatibility and clarity.
- Example: *"Merge the two sets of changes by adding all new enum constants from both sides, ensuring minimal and backward-compatible modifications."*

---

### `steps` Array
- Must contain **one or more** strings.
- Each string describes a **specific, actionable step** to follow in the order given.
- Steps should:
  - Reference relevant files or code sections explicitly.
  - Specify what to add, modify, or remove.
  - Provide guidance for placement and formatting.
  - Include any validation or verification requirements.

---

### `resolution` String
- A clear and concise statement of the **final state** after completing the steps.
- Should include the exact elements added/changed/removed, and any constraints or preservation rules.
- Example: *"Include all new enum constants: LOGGER_CLASS, JMX_EXPOSE_ENABLED, UPDATE_CHECK_DISABLED, and APPLICATION_NAME, with comments. Do not modify existing constants beyond addition."*
